# SDC Devel

https://www.drupal.org/project/sdc_devel

> Provides validation and developer tooling for Single Directory Components.

**Vortex** ships the [SDC Devel](https://www.drupal.org/project/sdc_devel)
Drupal module to validate the [Single Directory Components](https://www.drupal.org/docs/develop/theming-drupal/using-single-directory-components)
in the custom theme - checking component definitions, schemas, and templates
for errors before they surface in the site.

## Usage

Validation runs through Drush against a provisioned site, so the site must be
built and running first:

import Tabs from '@theme/Tabs';
import TabItem from '@theme/TabItem';

<Tabs>
  <TabItem value="ahoy" label="Ahoy" default>
    ```shell
    ahoy lint-sdc
    ```
  </TabItem>
  <TabItem value="docker-compose" label="Docker Compose">
    ```shell
    docker compose exec cli vendor/bin/drush sdc-devel:validate your_site_theme
    ```
  </TabItem>
</Tabs>

`ahoy lint-sdc` validates the components of the custom theme and fails when the
validator reports critical issues, errors, or warnings.

## Configuration

The validator needs no configuration file: it discovers the components of the
theme passed to `drush sdc-devel:validate` (the theme's `components/`
directory).

The shipped [theme scaffold](../drupal/theme-scaffold.mdx#single-directory-components)
includes an example `button` component that passes validation and can be used
as a starting point.

## Ignoring fail in continuous integration pipeline

This tool runs in the continuous integration pipeline by default (on the first
test container - see [Test parallelism](../continuous-integration/parallelism.mdx))
and fails the build if there are any violations.

Set the `VORTEX_CI_SDC_DEVEL_IGNORE_FAILURE` environment variable to `1` to
ignore failures. The tool will still run and report violations, if any.
