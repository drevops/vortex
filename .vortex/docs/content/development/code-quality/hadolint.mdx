# Hadolint

https://github.com/hadolint/hadolint

> A smarter Dockerfile linter that helps you build best practice container
> images.

Hadolint checks Dockerfiles against best practices, such as pinning the
versions of installed packages, and runs ShellCheck over the shell commands
in `RUN` instructions. **Vortex** lints the Dockerfiles in `.docker`, which
build the images for its services, with the default rules. Where a rule
doesn't fit, the Dockerfile carries a `hadolint ignore=` directive with the
reason next to it, such as `DL3018` where the package set tracks the pinned
base image.

## Installation

:::note

**Vortex** doesn't install Hadolint locally. Follow the
[instructions](https://github.com/hadolint/hadolint#install) to install it
on your system.

In CI, Hadolint runs from its official Docker image.

:::

The installer selects Hadolint by default. Deselecting it in the
`Development tools` question removes the continuous integration step from
every supported provider. The `hadolint ignore=` directives stay in the
Dockerfiles, so a check you run by hand still skips the same rules.

## Usage

```shell
hadolint .docker/*.dockerfile
```

## Ignoring

To ignore rules for the whole file, add a `global ignore` directive to the
file header:

```Dockerfile
# hadolint global ignore=DL3003,DL3006,SC1035
FROM ubuntu
```

To ignore rules for the next instruction only:

```Dockerfile
FROM ubuntu

# hadolint ignore=DL3003,SC1035
RUN cd /tmp && echo "hello!"
```

## Continuous integration

Hadolint runs in the `lint` job of the [continuous integration
pipeline](../../continuous-integration/README.mdx) and fails the build on
violations. It lints every file in `.docker` that's named `Dockerfile` or
ends in `.dockerfile`.

### Ignoring failures

Set `VORTEX_CI_HADOLINT_IGNORE_FAILURE` to `1` to let the build pass anyway.
Hadolint still runs and prints every violation in the job log, so you can
see what you're letting through.

➡️ See [Continuous integration > Ignore tool
failures](../../continuous-integration/README.mdx#ignore-tool-failures)
