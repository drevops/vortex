# Twig CS Fixer

https://github.com/VincentLanglet/Twig-CS-Fixer

> The missing checkstyle for twig!
>
> Twig CS Fixer aims to be what phpcs is to php. It checks your codebase for
> violations on coding standards.

Twig CS Fixer checks Twig templates for the formatting problems PHPCS
catches in PHP: indentation, spacing around delimiters and operators,
trailing whitespace, quote style, and trailing commas. Most of its rules
can also fix what they find.
**Vortex** comes with a [pre-configured Twig CS Fixer
ruleset](https://github.com/drevops/vortex/blob/main/.twig-cs-fixer.php) for
Drupal projects.

## Configuration

See [configuration
reference](https://github.com/VincentLanglet/Twig-CS-Fixer/blob/main/docs/configuration.md).

All global configuration lives in the
[`.twig-cs-fixer.php`](https://github.com/drevops/vortex/blob/main/.twig-cs-fixer.php)
file.

The ruleset uses the `TwigCsFixer` standard with a 2-space indent. It also
turns on the rules that can't fix what they find, which Twig CS Fixer skips
by default, so `lint` reports problems such as badly named variables too.
It registers Drupal's `trans` tag parser as well, so templates that use
`{% trans %}` blocks parse.

Targets include custom modules and themes.

Adding or removing targets:

```php
$finder = new TwigCsFixer\File\Finder();
$finder->in(__DIR__ . '/web/modules/custom');
$finder->in(__DIR__ . '/web/themes/custom');
```

## Ignoring

To exclude a directory from linting, call `$finder->exclude()` in the
[`.twig-cs-fixer.php`](https://github.com/drevops/vortex/blob/main/.twig-cs-fixer.php)
file. The call drops the directory from the set of linted files and leaves
every rule enabled:

```php
$finder->exclude('myCustomDirectory');
```

Every error has an identifier in the form `A.B:C:D`, where:

- `A`: the rule short name (mainly made from the class name)
- `B`: the error identifier (like the error level or a specific name)
- `C`: the line the error occurs on
- `D`: the position of the token in that line

All 4 parts are optional: `A`, `A.B`, `A.B:C`, `A.B:C:D`, `A:C`, `A:C:D`,
and `A::D` all work. To find the identifier of an error you want to ignore,
run the linter command with the `--debug` option.

To ignore all Twig CS Fixer rules in a file, add this comment to the file
header:

```twig
{# twig-cs-fixer-disable #}
```

To ignore a specific rule in a file, add this comment to the file header:

```twig
{# twig-cs-fixer-disable A.B:C:D #}
```

Twig CS Fixer doesn't support ignoring code blocks.

To ignore only the current line:

```twig
{{ token }} {# twig-cs-fixer-disable-line A.B:C:D #}
```

To ignore only the next line:

```twig
{# twig-cs-fixer-disable-next-line A.B:C:D #}
{{ token }}
```

## Continuous integration

Twig CS Fixer runs in the `lint` job of the [continuous integration
pipeline](../../continuous-integration/README.mdx) and fails the build on
violations.

### Ignoring failures

Set `VORTEX_CI_TWIG_CS_FIXER_IGNORE_FAILURE` to `1` to let the build pass
anyway. Twig CS Fixer still runs and prints every violation in the job
log, so you can see what you're letting through.

➡️ See [Continuous integration > Ignore tool
failures](../../continuous-integration/README.mdx#ignore-tool-failures)
