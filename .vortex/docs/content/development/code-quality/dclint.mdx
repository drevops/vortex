# DCLint

https://github.com/zavoloklom/docker-compose-linter

> A command-line tool for validating and enforcing best practices in Docker
> Compose files.

DCLint checks Docker Compose files against best practices, such as quoted
port mappings and a consistent order of keys within each service, so
`docker-compose.yml` stays readable as services come and go.
**Vortex** comes with a [pre-configured DCLint
ruleset](https://github.com/drevops/vortex/blob/main/.dclintrc) for its
Docker Compose files.

## Installation

:::note

**Vortex** doesn't install DCLint locally. Follow the
[instructions](https://github.com/zavoloklom/docker-compose-linter#installation)
to install it on your system.

In CI, DCLint runs from its official Docker image.

:::

The installer selects DCLint by default. Deselecting it in the
`Development tools` question removes the `.dclintrc` configuration file and
the continuous integration step from every supported provider.

## Usage

```shell
dclint .
```

## Configuration

Global configuration lives in the
[`.dclintrc`](https://github.com/drevops/vortex/blob/main/.dclintrc) file.
It turns off 4 rules (`no-build-and-image`, `services-alphabetical-order`,
`no-unbound-port-interfaces`, and `require-project-name-field`) and
configures `service-keys-order` with 8 groups of keys. That rule keeps the
keys of every service in `docker-compose.yml` in the same order, from core
definitions such as `build` and `image` to operational metadata such as
`labels`. Diffs then stay small and services stay comparable.

## Ignoring

To ignore all DCLint rules in a file, add this comment to the file header:

```yaml
# dclint disable
services:
  cli:
    build: .
```

To ignore specific rules for a single line, place a `disable-line` directive
on its own line immediately before it:

```yaml
services:
  nginx:
    ports:
      # dclint disable-line require-quotes-in-ports
      - 8080:8080
```

## Continuous integration

DCLint runs in the `lint` job of the [continuous integration
pipeline](../../continuous-integration/README.mdx) and fails the build on
violations.

### Ignoring failures

Set `VORTEX_CI_DCLINT_IGNORE_FAILURE` to `1` to let the build pass anyway.
DCLint still runs and prints every violation in the job log, so you can see
what you're letting through.

➡️ See [Continuous integration > Ignore tool
failures](../../continuous-integration/README.mdx#ignore-tool-failures)
