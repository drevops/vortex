# Testing

import AsciinemaPlayer from '@site/src/components/AsciinemaPlayer';

**Vortex** ships 3 test frameworks, configured and wired into the
continuous integration pipeline, so the first test you add runs in CI with
no extra setup. Each covers a different layer. [PHPUnit](phpunit.mdx) tests
your custom PHP code with unit, kernel, functional, and functional
JavaScript tests. [Behat](behat.mdx) runs Behavior-Driven Development (BDD)
scenarios end to end against the site, in a real browser when a scenario
needs JavaScript. [Jest](jest.mdx) unit-tests the JavaScript behaviors in
your custom modules.

| Framework              | Covers                                                    | Command         |
|------------------------|-----------------------------------------------------------|-----------------|
| [PHPUnit](phpunit.mdx) | Unit, kernel, functional, and functional JavaScript tests | `ahoy test`     |
| [Behat](behat.mdx)     | BDD end-to-end tests in a real browser                    | `ahoy test-bdd` |
| [Jest](jest.mdx)       | JavaScript unit tests                                     | `ahoy test-js`  |

## Running

```shell
ahoy test                        # Run all PHPUnit test suites.
ahoy test-unit                   # Run PHPUnit unit tests.
ahoy test-kernel                 # Run PHPUnit kernel tests.
ahoy test-functional             # Run PHPUnit functional tests.
ahoy test-functional-javascript  # Run PHPUnit functional JavaScript tests.
ahoy test-bdd                    # Run Behat tests.
ahoy test-js                     # Run Jest tests.
```

Each framework page lists the Docker Compose equivalents and the options for
running a single file, a tag, or a filter.

### Run unit, kernel, and functional tests

`ahoy test` runs all the PHPUnit test suites: unit, kernel, functional, and
functional JavaScript.

## Reports and coverage

[PHPUnit](phpunit.mdx#reports) and [Behat](behat.mdx#reports) write JUnit
reports under `.logs/test_results/<tool>/`, and
[PHPUnit](phpunit.mdx#coverage) and [Jest](jest.mdx#coverage) write coverage
reports under `.logs/coverage/<tool>/`. The continuous integration pipeline
stores them as artifacts.

## Continuous integration

Tests run in the `build` job of the continuous integration pipeline, which
runs on 2 parallel containers by default. PHPUnit and Jest run on the first
container, and Behat spreads its scenarios across every container (see [Test
parallelism](../../continuous-integration/README.mdx#test-parallelism)).

Each framework has a `VORTEX_CI_<TOOL>_IGNORE_FAILURE` variable
(`VORTEX_CI_PHPUNIT_IGNORE_FAILURE`, `VORTEX_CI_BEHAT_IGNORE_FAILURE`,
`VORTEX_CI_JEST_IGNORE_FAILURE`). Set it to `1` and the build passes despite
failing tests, while the tool still runs and reports them (see [Ignore tool
failures](../../continuous-integration/README.mdx#ignore-tool-failures)).

## Project conventions

Project-specific test writing conventions (user story format, standard user
types, test class structure, test data conventions) live in your project's
`docs/testing.md` file. The installer scaffolds it when you install
**Vortex**, and your project team keeps it up to date.
