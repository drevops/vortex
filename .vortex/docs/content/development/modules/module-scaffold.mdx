# Module scaffold

The [module
scaffold](https://github.com/drevops/vortex/tree/main/web/modules/custom/ys_base),
`ys_base`, is a working custom module to build your project's own code on.
It comes with a deploy file and a test scaffold already in place.

We recommend keeping a custom `ys_base` module in your project to hold
general-purpose code that doesn't belong in a dedicated, feature-specific
module.

The `ys` prefix abbreviates your project's machine name (`your_site` here).
We recommend the same prefix for all your custom modules and the site
machine name for the theme, so each module and theme shows which project it
belongs to. The installer suggests both: a prefix of up to 4 letters
abbreviated from the machine name, and the machine name itself as the theme
name.

:::info Token replacement

The `your_site` and `ys` names, and the other tokens like them, are
placeholders. The installer replaces them with your project's own names when
you install **Vortex**.

:::

## Deploy file

The
[`ys_base.deploy.php`](https://github.com/drevops/vortex/blob/main/web/modules/custom/ys_base/ys_base.deploy.php)
file is a Drush deploy file: Drush runs each of its `ys_base_deploy_*()`
functions once, during site [provisioning](../provision.mdx), and records
which ones have run. Its single hook,
`ys_base_deploy_install_active_theme()`, installs the core front-end theme
and sets it as the default, then does the same for the custom theme when the
project has one.

## Demo module

The `ys_demo` module demonstrates the integration patterns for 3
contributed modules:

- [Drupal helpers](drupal-helpers.mdx) - utility facades for deploy hooks
- [Generated Content](generated-content.mdx) - plugin-based content
  generation
- [Testmode](testmode.mdx) - content filtering during Behat tests (declared
  as a dependency, so it installs together with `ys_demo`)

The demo module ships a pages view at `/pages` and a generated content
plugin that populates it. It also ships the deploy hooks that place a
counter block, add the `Pages` menu link, and register the view with
Testmode. The counter block, with its CSS, JavaScript, and Twig template,
also exercises the test tooling. It has Unit, Kernel, and
FunctionalJavascript PHPUnit tests, a Jest test, and the `counter.feature`
Behat feature.

## Other shipped modules

2 more custom modules ship alongside the scaffold and demo modules:

- `ys_search` - configures the Search API index, the Solr server, and the
  search view for the [Solr service](../environment/docker.mdx#services),
  and brings in the `workflows` and `content_moderation` core modules. On
  install it uninstalls core's `search` module, and its deploy hook attaches
  an editorial workflow to the `page` content type. It ships only with the
  Solr service.
- `ys_migrate` - a demo migration module that migrates the `categories`
  table of the second database into `tags` terms. It ships only with the
  migration feature (see [Migrations](../migrations.mdx)).

## Tests scaffold

The module's `tests` directory holds a working example test and a base
class for each PHPUnit test type: Unit, Kernel, Functional, and
FunctionalJavascript. A new test then starts from something that already
runs. It ships when PHPUnit is selected during installation.

Its `Traits` directory adds 5 helper traits for writing tests: `ArrayTrait`,
`AssertTrait`, `BrowserHtmlDebugTrait`, `MockTrait`, and `ReflectionTrait`.
Remove the ones you don't need.
