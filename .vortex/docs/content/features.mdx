  <VerticalTab>💧 Drupal | Pre-configured Composer project</VerticalTab>
  <VerticalTabPanel>

    A [Drupal 11](https://www.drupal.org/project/drupal) project with
    environment-aware settings, module and theme scaffolds, and
    pre-configured contributed modules.

    ### Composer-based project

    - Latest Drupal 11 release on
      [PHP](https://www.php.net/) 8.4, managed with
      [Composer](https://getcomposer.org/) and
      [Drush](https://www.drush.org/) 13
    - Configurable webroot directory to fit the hosting provider
    - Patches applied with
      [Composer Patches](https://github.com/cweagans/composer-patches)

    ### Settings and environment detection

    - Pre-configured [general
      settings](https://github.com/drevops/vortex/blob/main/web/sites/default/settings.php)
      with the database connection read from environment variables
    - Environment type detection for `local`, `ci`, `dev`, `stage`, and
      `prod` on every supported hosting provider
    - Per-module settings overrides for each environment type
    - Unit tests for the settings, shipped with the project

    ### Module and theme scaffolds

    - [Custom module
      scaffold](https://github.com/drevops/vortex/blob/main/web/modules/custom/ys_base)
    - [Custom theme
      scaffold](https://github.com/drevops/vortex/blob/main/web/themes/custom/your_site_theme)
      with Single Directory Components
    - [Tests
      scaffold](https://github.com/drevops/vortex/blob/main/web/modules/custom/ys_base/tests)
    - Opt-in [Storybook](https://storybook.js.org/) component library,
      rendered by Drupal and published at `/storybook` in the `local`, `ci`,
      and `dev` environments

    ### Contributed modules

    Up to 26 contributed modules ship configured for each environment:

    - Environment safety:
      [Environment Indicator](https://www.drupal.org/project/environment_indicator),
      [Reroute Email](https://www.drupal.org/project/reroute_email),
      [Shield](https://www.drupal.org/project/shield), and
      [Stage File Proxy](https://www.drupal.org/project/stage_file_proxy)
    - Search and performance:
      [Search API](https://www.drupal.org/project/search_api) with
      [Search API Solr](https://www.drupal.org/project/search_api_solr),
      [Redis](https://www.drupal.org/project/redis), and
      [Fast 404](https://www.drupal.org/project/fast_404)
    - Security: [ClamAV](https://www.drupal.org/project/clamav) and
      [Security Kit](https://www.drupal.org/project/seckit)
    - Content and SEO: [Pathauto](https://www.drupal.org/project/pathauto),
      [Redirect](https://www.drupal.org/project/redirect),
      [XML sitemap](https://www.drupal.org/project/xmlsitemap), and
      [RobotsTxt](https://www.drupal.org/project/robotstxt)
    - Development: [Devel](https://www.drupal.org/project/devel),
      [Config Split](https://www.drupal.org/project/config_split),
      [Generated Content](https://www.drupal.org/project/generated_content),
      [Testmode](https://www.drupal.org/project/testmode), and
      [Drupal Helpers](https://www.drupal.org/project/drupal_helpers)
    - Migrations: [Migrate Plus](https://www.drupal.org/project/migrate_plus)
      and [Migrate Tools](https://www.drupal.org/project/migrate_tools), with
      an optional second database as the migration source

    ➡️ See [Settings](/docs/development/settings) and
    [Contributed modules](/docs/development/modules/contributed-modules)

  </VerticalTabPanel>

  <VerticalTab>💻 Local Development | Containerized development environment</VerticalTab>
  <VerticalTabPanel>

    Containerized development environment with short project commands.

    ### Docker Compose and Ahoy

    - [Docker Compose](https://docs.docker.com/compose/) for service
      orchestration
    - [Ahoy](https://github.com/ahoy-cli/ahoy) for short project commands,
      with support for custom commands
    - [Pygmy](https://github.com/pygmystack/pygmy) for local domain names,
      SSH agent forwarding, and mail capture
    - Container images from [Lagoon](https://lagoon.sh/), the same images
      that run on Lagoon hosting

    ### Services

    - [Nginx](https://nginx.org/) and [PHP-FPM](https://www.php.net/) 8.4,
      with a static maintenance page that 1 variable switches on
    - [MySQL](https://www.mysql.com/) 8.4, or a database container image
      with the data built in
    - [Valkey](https://valkey.io/) 8 for caching
    - [Apache Solr](https://solr.apache.org/) 9 for search
    - [ClamAV](https://www.clamav.net/) for scanning uploaded files
    - [Selenium Chromium](https://hub.docker.com/r/selenium/standalone-chromium)
      for browser tests

    ### Developer tools

    - [Xdebug](https://xdebug.org/) for debugging, switched on with
      `ahoy debug`
    - [PCOV](https://github.com/krakjoe/pcov) for code coverage
    - Custom PHP settings for each container in `.docker/config/`
    - `ahoy doctor` to check the environment and report problems
    - `ahoy info` to show the site URL, database credentials, and service
      addresses

    :::note Planned features

    Support for [DDEV](https://ddev.com/) and [Lando](https://lando.dev/)
    is on the [roadmap](/docs/contributing/roadmap).

    :::

    ➡️ See [Environment](/docs/development/environment)

  </VerticalTabPanel>

  <VerticalTab>🏗️ Continuous Integration | Continuous integration configurations</VerticalTab>
  <VerticalTabPanel>

    Continuous integration and deployment, with the same pipeline on every
    supported provider.

    ### CI providers

    - [GitHub Actions](https://github.com/features/actions) pipeline
    - [CircleCI](https://circleci.com/) pipeline
    - Every job runs in the
      [`drevops/ci-runner`](https://github.com/drevops/ci-runner) image, so
      each run gets the same tools

    ### Pipeline

    - _Lint_ the code without provisioning a site
    - _Fetch the database_ from the hosting provider and cache it for the
      day, with a nightly refresh of the database container image
    - _Build_ and test a fully provisioned site, with
      [Behat](https://docs.behat.org/en/latest/) tests split
      across parallel containers
    - _Deploy_ the site to the hosting provider after the checks pass

    ### Containerized environments

    - Drupal runs in the same containerized stack as local development
    - Identical PHP version, dependency versions, tooling, and
      configuration

    ### Security audit

    - A separate workflow that scans for committed secrets with
      [Gitleaks](https://github.com/gitleaks/gitleaks)
    - Dependency audit with
      [`composer audit`](https://getcomposer.org/doc/03-cli.md#audit) and
      [`npm audit`](https://docs.npmjs.com/cli/commands/npm-audit)
    - Findings uploaded to
      [GitHub code scanning](https://docs.github.com/en/code-security/code-scanning)

    ### Pipeline flow control

    - Pipeline triggered by pushes to the configured branches and tags, or
      manually
    - Skip deployments for specific branches or pull requests, or gate them
      on a pull request label
    - Ignore the failures of a single tool without changing the pipeline
      configuration
    - Fail the build when it leaves the working tree dirty

    ### Artifacts and code coverage

    - Test results and build artifacts stored with each run
    - Code coverage check with a coverage summary comment on the pull
      request
    - Optional upload of coverage reports to
      [Codecov](https://codecov.io/)

    ➡️ See [Continuous integration](/docs/continuous-integration)

  </VerticalTabPanel>

  <VerticalTab>☁️ Hosting Integrations | Integrations with cloud hosting providers</VerticalTab>
  <VerticalTabPanel>

    ### Acquia

    > A Drupal-optimized hosting platform built to empower your team.

    - [Acquia](https://www.acquia.com/) hosting integration
    - Fetch the database from an Acquia environment
    - Copy the database and files between environments
    - Purge the [Varnish](https://varnish-cache.org/) cache
    - Code artifact deployments with
      [`git-artifact`](https://github.com/drevops/git-artifact)
    - Deployment automation with Cloud Hooks

    ### Lagoon

    > Lagoon, the developer-focused application delivery platform

    - [Lagoon](https://lagoon.sh/) hosting integration
    - Containerized stack that runs in production
    - Fetch the database from a Lagoon environment
    - Deployments through the
      [Lagoon CLI](https://github.com/uselagoon/lagoon-cli), including pull
      request environments
    - Pull request environments removed when the pull request closes
    - Custom tasks and a static maintenance page

    ### Other hosting providers

    - Webhook deployments for any provider that accepts a deployment URL
    - Database fetch from a URL, FTP, S3, or a container registry

    :::note

    Integration with [Upsun](https://upsun.com/) is on the
    [roadmap](/docs/contributing/roadmap).

    :::

    ➡️ See [Hosting](/docs/hosting) and [Deployment](/docs/deployment)

    - [PHPUnit](https://phpunit.de/) for unit, kernel, functional, and

    - [Behat Steps](https://github.com/drevops/behat-steps) library to
      speed up test writing, with direct access to Drupal APIs for faster
      test runs
    - [Behat Screenshot](https://github.com/drevops/behat-screenshot) for

    - [Gherkin Lint](https://github.com/dantleech/gherkin-lint-php) for test

  <VerticalTab>✨ AI | Built-in support for AI coding agents</VerticalTab>
  <VerticalTabPanel>

    Project configuration that gives AI coding agents the context they need
    from the first session.

    ### Agent-agnostic configuration

    - [`AGENTS.md`](https://agents.md/) works with any AI tool that reads
      it, including [Cursor](https://cursor.com/) and
      [GitHub Copilot](https://github.com/features/copilot)
    - [`CLAUDE.md`](https://github.com/drevops/vortex/blob/main/CLAUDE.md)
      for [Claude Code](https://www.claude.com/product/claude-code) imports
      `AGENTS.md`, so there's only 1 set of instructions to maintain
    - A checked-in Claude Code settings file pre-approves every `ahoy`
      command
    - Custom skills committed under `.claude/skills/` are shared with the
      team

    ### Project-level documentation stored within the codebase

    - Decisions for testing, CI, deployment, and release processes
    - Operational guides from
      [vortextemplate.com](https://www.vortextemplate.com/docs)
    - Agents receive the same layered guidance as human developers

    ### Pre-configured context

    - Development commands, critical rules, and directory layout ship with
      the project
    - Agents can start contributing without lengthy onboarding

    ### Documentation caching

    - Agents fetch and cache operational docs for reuse across sessions
    - Reduces repeated web requests and speeds up agent responses

    ### AI code review

    - Opt-in [CodeRabbit](https://www.coderabbit.ai/) configuration that
      reviews pull requests against the project's documented conventions
    - Comments limited to correctness, security, performance, and
      maintainability, with linting left to the project's own linters

    ➡️ See [AI](/docs/development/ai)

  </VerticalTabPanel>

  <VerticalTab>⚙️ Automations | Useful automations and scripts</VerticalTab>
  <VerticalTabPanel>

    ### Identical operations across environments

    - Scripts for common tasks, shipped as the
      [`drevops/vortex-tooling`](https://packagist.org/packages/drevops/vortex-tooling)
      Composer package, run the same way in every environment
    - Customization through environment variables
    - Database sourced from the hosting provider, a URL, FTP, S3, or a
      container image seeded with
      [MariaDB Drupal Data](https://github.com/drevops/mariadb-drupal-data)

    ### Provisioning

    - Provision from a database dump or from an installation profile
    - Database sanitization outside production
    - Database updates, configuration import, and deploy hooks on every
      deployment
    - Opt-in check that fails provisioning when updates change the
      configuration

    ### Deployment notifications

    - Deployment notifications to email, [Slack](https://slack.com/),
      [GitHub](https://github.com/),
      [Jira](https://www.atlassian.com/software/jira),
      [New Relic](https://newrelic.com/), a webhook, and
      [Diffy](https://diffy.website/)
    - Deployment status on the GitHub pull request
    - Deployed environment details posted as a Jira comment
    - Deployment markers in New Relic

    ### Automated dependency management

    - Automated dependency updates with
      [Renovate](https://www.mend.io/renovate/), as the hosted app or
      self-hosted in CI for projects with restricted third-party access
    - Separate groups and schedules for Drupal core, PHP and JavaScript
      packages, container images, CI tools, and GitHub Actions
    - Auto-merge flag for each group
    - 14-day minimum release age for new releases, except Drupal core

    ### Development workflow automation

    - [Pull request
      template](https://github.com/drevops/vortex/blob/main/.github/PULL_REQUEST_TEMPLATE.md)
      for consistent reviews
    - [Release Drafter](https://github.com/release-drafter/release-drafter)
      for draft release notes, numbered with
      [CalVer](https://calver.org/) or [SemVer](https://semver.org/)
    - [Auto Author Assign](https://github.com/toshimaru/auto-author-assign)
      for pull request assignments
    - [Label Merge Conflict](https://github.com/eps1lon/actions-label-merge-conflict)
      for flagging pull requests with merge conflicts

    ➡️ See [Provision](/docs/development/provision),
    [Notifications](/docs/deployment/notifications), and
    [Dependency updates](/docs/development/dependency-updates)

  <VerticalTab>🌀 Vortex | Consistency across your projects</VerticalTab>
  <VerticalTabPanel>

    **Vortex** keeps your **Vortex**-onboarded projects consistent and
    reliable, so you can depend on future updates and improvements.

    ### Product maturity

    - **Vortex** has been in development and production use since 2017,
      across education, government, commercial, healthcare, not-for-profit,
      financial services, and technology sectors.
    - Kept current with the latest Drupal, PHP, containerization, CI/CD
      practices, and tooling.
    - Managed as a product with a dedicated team and a
      [roadmap](/docs/contributing/roadmap).
    - Released monthly with new features, improvements, and bug fixes.

    ### Multi-layered automated testing for every change

    - Test coverage for the containerized stack
    - Test coverage for the tooling configuration
    - Unit tests and coverage reporting for automation scripts
    - Functional test coverage for scripts: run all commands as a developer
      would
    - Automated documentation site generation and validation

    ### Vortex installation and updates

    - Standalone installer application for installing and updating
      **Vortex** projects
    - Interactive prompts, or prepared answers for scripts and AI agents
    - Install and update from the most recent version or a specific
      **Vortex** Git SHA
    - `ahoy update-vortex` to update an existing project
    - A test suite that guards project updates

    ➡️ See [Installation](/docs/installation) and
    [Updating Vortex](/docs/updating-vortex)
