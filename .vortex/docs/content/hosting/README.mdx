# Hosting

This section covers where your site _runs_. It's for the lead or DevOps
engineer who hosts a project built from **Vortex**, and for anyone choosing
where to host it.

**Vortex** integrates with 2 hosting providers, [Acquia](acquia/README.mdx)
and [Lagoon](lagoon/README.mdx). Each provider has the same set of pages:

| Page | Covers | Acquia | Lagoon |
|------|--------|--------|--------|
| Overview | What a site gets on the platform, what runs on each deployment and how the site detects its environment | [Overview](acquia/README.mdx) | [Overview](lagoon/README.mdx) |
| Setup | What must exist on the platform before the first deployment | [Set up the Acquia application](acquia/setup.mdx) | [Set up the Lagoon project](lagoon/setup.mdx) |
| Domains | Production domains, DNS and certificates | [Domains and certificates](acquia/domains.mdx) | [Domains and certificates](lagoon/domains.mdx) |
| Operations | Logging in, Drush, databases, files, tasks and taking the site offline | [Routine operations](acquia/operations.mdx) | [Routine operations](lagoon/operations.mdx) |
| Migration | Moving a live site from another host | [Migrate a site to Acquia](acquia/migrate.mdx) | [Migrate a site to Lagoon](lagoon/migrate.mdx) |

For any other provider, choose **Other** or **None** at the installer's
**Hosting provider** prompt. With either answer, the installer leaves out
the Acquia and Lagoon integration files, such as their settings files, the
Acquia hooks and `.lagoon.yml`. The deployment type then defaults to
`webhook`. The [roadmap](../contributing/roadmap.mdx) lists the hosting
integrations under consideration.

The [Deployment](../deployment/README.mdx) section covers how code _gets
to_ a provider: deployment types, triggers and skip rules.

## Hosting providers vs environments

**Hosting providers** are the _platforms_ where your _environments_ run.
They can be cloud-based or on-premises. They provide the infrastructure for
the web server, the database and the other services your site needs.

**Environments** are the contained _bundles_ of those services that run
your website. Each one is a stage of your deployment and release lifecycle,
from local development to production. A single hosting provider can run
several of them.

Hosting providers typically offer DEV, STAGE and PROD environments. Some
also run short-lived environments for a single change, called "preview",
"on-demand" or "feature" environments. They let you test a change in
isolation before you merge it into the main codebase.

**Vortex** detects the environment type at runtime and stores it in
`$settings['environment']`, so your settings can change the site's behavior
for each type.

➡️ See [Development > Settings > Environment type
detection](../development/settings.mdx#environment-type-detection)
