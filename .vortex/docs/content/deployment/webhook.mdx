# Webhook deployment

Webhook deployment triggers a remote deployment by calling an HTTP endpoint.
Use it with external systems or custom deployment pipelines that expose a
webhook URL.

:::note

This is a deployment _type_: it triggers the deployment itself. To call a
webhook _about_ a deployment (for example, to tell a monitoring system one
happened), use the [webhook notification channel](notifications/webhook.mdx)
instead.

:::

## How it works

When `webhook` is included in `$VORTEX_DEPLOY_TYPES`, the deployment script
calls the configured webhook URL with `curl`, using the configured HTTP
method and following redirects. It sends no deployment data, so anything
the receiving end needs has to be in the URL itself. The deployment passes
when the response status matches `VORTEX_DEPLOY_WEBHOOK_RESPONSE_STATUS`,
and fails otherwise.

## Configuration

### Environment variables

| Variable | Required | Default | Location | Description |
|----------|----------|---------|----------|-------------|
| `VORTEX_DEPLOY_WEBHOOK_URL` | **Yes** | | CI | The webhook URL to call |
| `VORTEX_DEPLOY_WEBHOOK_METHOD` | No | `GET` | `.env` | HTTP method, for example `GET` or `POST` |
| `VORTEX_DEPLOY_WEBHOOK_RESPONSE_STATUS` | No | `200` | `.env` | Expected HTTP response status code |

### Setup

1. Add `webhook` to the `VORTEX_DEPLOY_TYPES` variable in your `.env` file:

   ```shell title=".env"
   VORTEX_DEPLOY_TYPES=webhook
   ```

2. Add `VORTEX_DEPLOY_WEBHOOK_URL` to your CI provider's environment
   variables and treat it as a secret. On GitHub Actions, the shipped
   workflow reads it from a repository variable of the same name. If the URL
   carries a token, change that line of the workflow to read from `secrets`
   instead.

## Use cases

- Triggering deployments on platforms that provide webhook endpoints
- Integrating with custom deployment orchestration systems
- Notifying external services when code is ready for deployment
