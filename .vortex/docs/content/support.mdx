# Support

This page is for anyone who uses **Vortex** or is evaluating it and needs
help. It lists where to get answers, from the documentation to community
and paid support. It also explains how to report a bug or a security issue.

If you're new to **Vortex**, start with the [Installation
guide](/docs/installation), then explore the [Features](/docs/features).

## 🛟 Getting help

### Self-help

Start here. These resources cover the common problems:

- 📖 **[Documentation](/docs)** - guides and references for every subsystem
- ❓ **[FAQs](/docs/faqs)** and
  **[Development FAQs](/docs/development/faqs)** - answers to adoption and
  day-to-day questions
- 🩺 **[Doctor](/docs/development/environment/doctor)** - run `ahoy doctor`
  to diagnose common local environment issues

A clean `ahoy doctor` run ends with
`[ OK ] All required checks have passed.` A failing check prints a `[FAIL]`
line, usually with a suggested fix, and stops the run.

  channel in Drupal Slack to get help from the community and core

## 🚨 Reporting issues

Before you report a problem, do the following:

- Check the existing issues on
  [GitHub](https://github.com/drevops/vortex/issues)
- Run diagnostics with `ahoy doctor`
- Review the [FAQs](/docs/faqs) for common solutions
- Reproduce the problem in a clean environment, if you can

Include the following in your report:

- System information from `ahoy doctor info`
- Steps to reproduce the problem
- Error messages and logs
- Your **Vortex** version, from the **Vortex** badge in your project's
  `README.md`
- Your configuration details

Read the `ahoy doctor info` report before you post it. In the binary paths
and the `docker info` output, the report redacts these values:

- Your username
- IPv4 addresses
- 36-character `ID:` values
- Hex strings of 40 or more characters

The rest of the report stays as printed, including the operating system
details and the `docker info` host name.

## 🔒 Security issues

Never report a security vulnerability in a public GitHub issue: email it to
[support@drevops.com](mailto:support@drevops.com), so a fix can ship before
the problem is public.
